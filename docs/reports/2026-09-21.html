🔐 AI Security Watch

Issue: LiteLLM MCP Streamable HTTP authentication bypass (CVE-2026-59822, CVSS 8.8)

Impact: Unauthenticated callers may reach MCP tooling and upstream credentials via a faulty OAuth2 passthrough fallback on versions before 1.84.0.

Who should care: Teams exposing LiteLLM as an AI gateway with MCP routes on the public internet.

Recommended action: Upgrade to LiteLLM ≥1.84.0; until patched, block external access to /mcp/ and rotate any keys that transited the proxy.

Issue: AI-assisted exploit chains against SSO-linked coding accounts (Hacktron / OpenAI, July incident; renewed reporting Sep 21)

Impact: Forum RCE plus OpenAI SSO misconfiguration enabled takeover of employee ChatGPT/Codex sessions and demonstration PR creation in internal GitHub — connectors to Slack and email were in scope.

Who should care: Developers using “Sign in with OpenAI” on community tools; enterprises linking Codex/Copilot-class agents to org GitHub.

Recommended action: Segregate SSO scopes per application; disable unnecessary forum SSO for staff; audit OAuth token audiences after third-party forum or plugin compromises.

Issue: Delayed public disclosure after third-party cyber evals (Google Gemini, May 2026)

Impact: Real organizations may not learn they were touched by benchmark agents until weeks later, limiting hardening and incident response.

Who should care: Security teams at companies with names common in CTF datasets; vendors contracting Irregular-style evaluators.

Recommended action: Contract 72-hour customer notification for any outbound agent connection; run egress deny-by-default in all agent eval networks.
