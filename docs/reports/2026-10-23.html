MCP Inspector OAuth URLs can trigger PowerShell code execution on Windows

Impact: ⭐⭐⭐⭐⭐Impact: 5 out of 5  |  Category: Security / Developer Tools

What happened: On October 21, 2026, GitHub published advisory GHSA-q978-78c7-phqw for @modelcontextprotocol/inspector versions 2.0.0 through 2.11.0. A remote MCP server can supply a malicious OAuth authorization URL that runs when Inspector auto-opens the browser on Windows or WSL.

Why it matters: The chain needs no tool approval and no model involvement. Patched releases ship in Inspector 2.12.0, which bumps the pinned open package to v11 with proper PowerShell escaping.

Adopt it — Upgrade Inspector to 2.12.0 and set MCP_AUTO_OPEN_ENABLED=false on untrusted servers.

Source: GitHub advisory (Oct 21, 2026)

🔐 AI Security Watch

Issue: MCP Inspector 2.0.0–2.11.0 executes attacker-chosen OAuth URLs via PowerShell on Windows and WSL during MCP connection.

Impact: Any developer machine running Inspector against an untrusted remote MCP server could face arbitrary code execution as the local user.

Who should care: Windows and WSL developers using MCP Inspector, Claude Desktop MCP tooling, or CI jobs that connect to third-party MCP servers.

Recommended action: Upgrade to @modelcontextprotocol/inspector 2.12.0 or later and disable auto-open with MCP_AUTO_OPEN_ENABLED=false when testing unknown servers.

Issue: Check Point flagged CVE-2026-55887 command injection in MCP Gateway versions 0.21.0 through 0.42.1 via Docker run argument fields.

Impact: Attackers who can influence gateway routing config may execute arbitrary host commands where MCP Gateway orchestrates Docker sandboxes.

Who should care: Platform teams running self-hosted MCP Gateway in front of agent tool fleets.

Recommended action: Upgrade MCP Gateway to 0.42.2 or later and restrict who can publish gateway route definitions.

Issue: OpenAI and Poland's NASK signed an October 23, 2026 agreement to collaborate on frontier AI safety and security research through the Polish AISI center.

Impact: The deal extends prior CERT Polska work that used OpenAI cyber-capable models to find MikroTik RouterOS flaws in July 2026.

Who should care: Security engineers building agent red teams and vendors preparing cross-border safety institute evaluations.

Recommended action: Track published joint evaluations for agent vulnerability patterns applicable to internal harness tests.

📚 Research Worth Reading

When Is a Memory Safe Enough to Act On? Action-Conditioned Verification for Long-Lived Agents

Problem: Long-lived agents reuse session memory for irreversible actions, yet stale entries need different checks depending on the planned action.

Key idea: AMV-Guard treats verification as a stopping problem: re-check only memory premises whose validation could change the next action.

Why developers should care: On ToolSandbox, the gate cut mean verification cost 33.9% while keeping 100% safe-proceed recall in the reported evaluation.

Paper: arXiv:2610.31446

Better Reasoning, Not Just Bigger Models: Structure-Grounded Uncertainty Reduction

Problem: Multi-turn agents often sound plausible while reasoning over incomplete observations without grounding hypotheses in structure.

Key idea: SGUR matches query graphs to hypothesis graphs and picks the next question that maximizes information gain without extra model training.

Why developers should care: On a PrimeKG diagnosis benchmark, SGUR reported 92.5% Hit@3 using about five times fewer tokens than strong Graph-RAG baselines.

Paper: arXiv:2610.30611
