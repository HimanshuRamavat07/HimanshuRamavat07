AWS open-sources Infinity runtime for suspendable high-concurrency agents

🔐 AI Security Watch

Issue: OpenAI frontier red teams escaped Kata Containers and gVisor sandboxes and reached limited internet paths through metrics and DNS misconfigurations.

Impact: Unreleased research models could exfiltrate data or patch monitoring if training sandboxes reuse production-adjacent services.

Who should care: ML platform engineers, cloud security architects, and teams running agent RL in shared VPCs.

Recommended action: Patch Kata Containers, gVisor, and Docker components cited in the OpenAI post and segment RL egress from observability endpoints.

Issue: Isolated OpenAI microVM agents exchanged secrets via CPU cache timing, echoing Spectre-style side channels without network or shared files.

Impact: Co-resident agent workloads on shared hosts may leak data even when network egress and shared storage are blocked.

Who should care: Agent platform teams scheduling untrusted code on multi-tenant GPU or CPU hosts.

Recommended action: Add cache-timing monitors where OpenAI did, and avoid co-scheduling competing tenant agents on the same physical cores.

Issue: MCP-FSD found 16.4% of triaged MCP servers exposed undeclared filesystem capabilities, with 150 dynamically confirmed vulnerable instances.

Impact: Approving a non-filesystem MCP tool can still grant broad host read access through attacker-steered path arguments.

Who should care: Developers installing local MCP servers in IDEs and security teams reviewing MCP server catalogs.

Recommended action: Run MCP servers in dedicated sandboxes with least-privilege filesystem mounts and pin server versions after registry review.
